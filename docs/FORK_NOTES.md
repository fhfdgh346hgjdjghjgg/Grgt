# Паспорт проекта (handoff для AI-агента)

Этот файл — контекст для продолжения работы над форком в любой новой сессии.
Агент: прочитай его целиком, затем продолжай с раздела «Текущий статус».
Каталог всех функций клиента (что, где включить, где код) — [`TELEWHITE_FEATURES.md`](TELEWHITE_FEATURES.md).

## Что это

Форк официального Telegram Desktop (tdesktop) под Windows x64, переименован в **Telewhite**.
Владелец: GitHub `lucudar` (Wkn). Пользователь — новичок, весь код пишет агент,
пользователь даёт идеи и правки. Общение — на русском.

20.10.2026 проект скопирован с полной историей из `lucudar/tdesktop` в
`fhgdh36436jghjgjg/331313` (ветки `dev` — по умолчанию — и `telewhite-mods`).
Служебные ветки апстрима (`master`, `nightly`, `calls` и т. п.) не копировались:
в них полный набор upstream-workflows, каждая запустила бы пачку многочасовых сборок.

## Схема работы

1. Пользователь присылает идею → агент вносит правку в отдельной ветке и открывает PR в `dev`.
2. GitHub Actions (workflow `.github/workflows/win.yml`) автоматически собирает `Telegram.exe`
   на каждый пуш в ветку.
3. Пользователь скачивает артефакт со страницы Actions, тестирует на своём ПК (Windows)
   и вливает PR в `dev`.
4. Если предыдущий PR ещё не влит, следующий открывается поверх его ветки (база PR —
   ветка предыдущего). После мерджа первого второй перенацеливается на `dev`
   (GitHub делает это сам, когда ветку первого удаляют).

## Что уже настроено

- CI урезан до одной сборки **Windows x64** (была матрица из 6 вариантов).
- Удалены workflows: linux, mac, mac_packaged, snap, docker.
- Удалены и апстримовские workflows-обслуживание: canary, issue-боты, winget, stale
  (форку-приложению они не нужны, только шум в CI). Остался только `win.yml`:
  `changelog.yml` удалён 20.10.2026 — он публикует GitHub Pages, которых у форка нет,
  и падал на каждом мердже апстрима.
- В `win.yml` добавлен `workflow_dispatch` (ручной запуск сборки).
- Все сборки идут на бесплатных `windows-latest`: апстрим собирает PR, теги и `nightly`
  на платных раннерах `depot-windows-latest-16`, в форке такие задачи висели бы в очереди
  вечно. PR из веток этого же репозитория отдельно не собираются — их проверяет
  push-прогон ветки (тот же коммит); PR из чужих форков собираются как обычно.
- API-ключи: если в Secrets репозитория заданы `TDESKTOP_API_ID` и `TDESKTOP_API_HASH`,
  сборка использует их, иначе — тестовые ключи (`-D TDESKTOP_API_TEST=ON`).
- Артефакт хранится 7 дней (у апстрима 1 день — не успевали скачать).
- С 21.10.2026 сборка **Release**: библиотеки собираются в обеих конфигурациях
  (`win.bat silent`), кэши под ключами `libs-release-` и `qt-release-`, приложение —
  `--config Release`, артефакт из `out\Release`. Холодная сборка новой ветки — около
  3–3,5 часов, дальше быстрее за счёт кэша (кэши GitHub видны только своей ветке и `dev`).
  Release-стадия breakpad собирает `dump_syms`, которому нужен ATL для закреплённого
  тулсета 14.44, а на раннере ATL есть только для новейшего: шаг «ATL for the 14.44
  toolset.» ставит `Microsoft.VisualStudio.Component.VC.14.44.17.14.ATL` при промахе кэша.
- Места на диске впритык. На образе Windows Server 2025 нет отдельного D:, всё лежит на C:
  (около 150 ГБ, свободно около 30). Шаг «Free disk space on C.» удаляет неиспользуемый
  предустановленный софт: Android, .NET SDK, LLVM, `C:\msys64`, Strawberry Perl, системный
  Rust, лишние версии Python, базы данных и т. п. `prepare.py` ставит свои msys64, perl и Rust.
  После мерджа 7.3.2 (+ ANGLE для Qt 6) старой очистки не хватило: библиотеки упали на
  `tg_owt` с «No space left on device». Свободное место печатается в начале и в конце шага
  очистки и в шаге «Disk space after libraries.».
- Апстрим синхронизирован до **7.3.2** (мердж 21.10.2026, батч 10, upstream `dev` на 21.10.2026).

## Как обновлять апстрим

```bash
git fetch --depth=3200 upstream dev
git merge upstream/dev
```

Конфликты ожидаемы только в `.github/workflows/*` (форк держит свою схему CI)
и в `Telegram/SourceFiles/window/main_window.cpp` (строка заголовка окна:
сохранять `u"Telewhite"_q`, у нового кода есть ещё `+ suffix`).

## Полезные факты

- Ветка по умолчанию: `dev`. Пуши в неё триггерят сборку (кроме изменений `**.md` и `docs/**`).
- Артефакт называется `Telegram x64`, содержит `Telegram.exe` (Release-конфигурация).
- Первая сборка ~1.5–3 часа (собираются все библиотеки), дальше быстрее за счёт actions/cache.
- Лицензия GPLv3: исходники форка открыты; нельзя использовать имя «Telegram» и оригинальную иконку как есть.
- Для правок интерфейса смотреть `.style`-файлы и `Telegram/Resources/`;
  идеи фич можно подсматривать в форках 64Gram, Kotatogram, AyuGram, Forkgram.
- Пути в этом репозитории отличаются от апстрима: `.style`-файлы лежат в
  `Telegram/SourceFiles/<area>/*.style` (не в `Telegram/Resources/style/`),
  палитра — `Telegram/lib_ui/ui/colors.palette`, настройки чата —
  `Telegram/SourceFiles/settings/sections/settings_chat.cpp`.
  `Telegram/Resources/langs/lang.strings` — в репозитории LF (на Windows git может
  отдать CRLF), без BOM; вставлять байтово, не меняя окончания строк.
- Перед правками `git submodule update --init --depth=1` (иначе нет `.style` и палитры).
- Стиль кода: табы, без комментариев-комментариев очевидного, `auto` для типов,
  строки через `u"..."_q`, новые настройки — через `writePref/readPref` (не QDataStream!).
- Требования к коммитам и стилю — в `AGENTS.md` и `REVIEW.md` в корне репозитория.

## Ускорение CI (на будущее, не применено)

- Не трогать `dev`, пока идёт сборка: в `win.yml` `concurrency: cancel-in-progress: true`
  по ветке — новый пуш в ту же ветку отменяет текущий прогон. Фичи пушить в отдельную ветку.
- Идеи: sccache/ccache для MSVC с кэшем в actions/cache; не собирать `Updater`;
  `-D DESKTOP_APP_DISABLE_*` для ненужного (webrtc/звонки — если не нужны);
  Ninja вместо MSBuild (уже `generator` в матрице).
